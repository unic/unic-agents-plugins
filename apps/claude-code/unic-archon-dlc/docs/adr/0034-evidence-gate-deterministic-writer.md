# 0034. The evidence gate is a deterministic script writer, never a self-judging prompt

**Status:** Accepted (2026-08-10, revised 2026-10-28)

## Context

Archon 0.7.0's `evidence_policy: { required: true }` ([ADR-0033](0033-archon-070-schema-target.md)) refuses terminal `completed` unless `evidence.json` exists in the run's `$ARTIFACTS_DIR` — but the engine checks presence only. Whatever writes that file **is** the gate, in the same sense [ADR-0012](0012-fresh-context-red-green-separation.md) already identified for red/green: a check that can grade its own homework is not a check.

An AI prompt node that both judges the build (reads `verification`/`goals-check` output, decides pass/fail) and writes `evidence.json` accordingly would be exactly that: a prompt that judges itself green and then certifies itself green, with nothing external constraining the two decisions to agree. This is the same failure mode the slopcheck gate and [ADR-0012](0012-fresh-context-red-green-separation.md)'s red/green isolation exist to prevent.

## Decision

A dedicated **script node**, `evidence`, is the only writer of `evidence.json`. It is deterministic code, not an AI judgment:

1. **Refuse a missing `$ARTIFACTS_DIR` loudly, before anything else.** The engine exports it to script nodes and this is the plugin's only read of it, so an absent value is a breach of the engine contract, not a red verdict — the node exits **non-zero** with a message naming the contract and the floor. The check tests falsiness rather than `undefined` because the empty-string case is the dangerous one: unset throws inside `join()`, but `join('', 'evidence.json')` returns a **relative** path and does not throw, so the node would log a successful write while the engine's presence gate read the real `$ARTIFACTS_DIR` and found nothing — a run failing closed with a success line in its log. Falling back to the Session dir is explicitly rejected: the gate reads only `$ARTIFACTS_DIR`, so a fallback would make that silent case permanent.
2. **Delete-first, both copies.** Remove any `$ARTIFACTS_DIR/evidence.json` **and** any mirrored `<artifacts_dir>/<slug>/evidence.json` left by a prior attempt before doing anything else — `$ARTIFACTS_DIR` is per-run but a resumed run reuses it ([ADR-0033](0033-archon-070-schema-target.md)), and the Session dir is reused too, so a stale file from a previous, since-superseded attempt would certify a tree that is no longer green. The mirror needs this more than the original: the engine's presence gate reads only the `$ARTIFACTS_DIR` copy, so deleting that copy alone would leave a stale mirror for the Session commit to stage and a reviewer to read after an attempt that failed before writing.
3. **Read, don't judge.** It reads what `verification` and `goals-check` already computed (via their `output_format`, not by re-running or re-interpreting anything): the `passed` boolean **and** the `failures` list, cross-checked, **and `verification`'s three-state `test_outcome`** ([ADR-0037](0037-config-declares-sdlc-needs.md)). The third state is why the two booleans are not enough on their own: a suite that could not run reports no failures, so on the booleans alone an absent result and a green result are the same fact. A `test_outcome` that is not `pass` is red here whatever the booleans say, and the node's own verdict — printed to stdout as JSON, because a `script:` node has no `output_format` — carries the same three states. `passed` alone is a self-report from the same prompt that wrote `failures`, so a `passed: true` beside a non-empty `failures` array would otherwise certify a tree whose own certificate listed the failures. Both prompts define `failures` as blockers only, so a non-empty list is a red verdict whatever the boolean says. This is a cross-check, not independence — only re-running the suite would give that, and [ADR-0023](0023-build-generic-red-green-refactor-loop.md) §5 rules it out.
4. **Write on every verdict.** The node writes `$ARTIFACTS_DIR/evidence.json` whatever the verdict, with the verdict, `test_outcome`, `unresolved_needs` and both failure arrays, so the file the engine demands says what failed. It then mirrors the file to `<artifacts_dir>/<slug>/evidence.json` (the Session-artifact home, [ADR-0015](0015-workflows-slug-artifact-home.md)), because `$ARTIFACTS_DIR` resolves outside the repo tree and is gone once `/cleanup` prunes the worktree, so without the mirror the file is invisible to a reviewer and to the node that commits the Session artefacts. The verdict, not the file's presence, decides how the run ends. Only `pass` opens a pull request, and any other verdict cancels the run with the work pushed ([ADR-0040](0040-build-verdict-decides-the-pull-request.md)). The engine's presence check stays, as a backstop for `evidence` ending without writing.
5. **`always_run: true`.** Its own exit code is a write op, not a verdict about the tree; a resumed run must re-derive presence from the CURRENT `verification`/`goals-check` output on every attempt, never trust that a file left by an earlier attempt describes the CURRENT tree.

**Rejected alternative: a prompt writes `evidence.json` when it judges itself green.** This was the first design considered and is recorded here specifically so it is not proposed again: it collapses judgment and certification into the same actor, the exact failure [ADR-0012](0012-fresh-context-red-green-separation.md) and the slopcheck gate exist to prevent for red/green and for dependency trust respectively. A script has no incentive to agree with itself; a prompt asked to both decide and attest does.

## Consequences

- `verification` and `goals-check` in `unic-dlc-build.yaml` carry a boolean `output_format` (`passed`, `failures`) alongside their existing prose verdicts, and `verification` adds `test_outcome` and `unresolved_needs` — the prose stays for the human at `build-pr-gate`; those fields are what the `evidence` node reads, and the engine's gate then checks only that `evidence` wrote the file.
- The `evidence` node depends on both and runs after them, before `report`; `report.md` is unaffected — it already folds in `$verification.output` and `$goals-check.output` verbatim.
- No other Box gains an evidence gate in this ADR. `/qa`, `/pr-review`, and `/explore` have their own verdict-reporting nodes (`e2e`, `coverage-gate`, `uat-prep`, …) but none currently reaches a terminal `completed` state whose evidence needs this exact deterministic-writer shape; extending the pattern there is a separate decision.
